Stripe churn signals: a field guide

Most small SaaS teams hear about churn from a "subscription canceled" email. By then the customer decided weeks ago. Stripe already records most of the warning signs. This page lists them, what each one means, and the first move to make.

Open source, MIT licensed Code on GitHub: stripe-churn-signals

The signals

SignalWhere it shows up in StripeWhat it meansFirst move
Scheduled cancellationcustomer.subscription.updated, cancel_at_period_end flips to trueThe customer already clicked cancel. You have until the period ends.A personal note that answers the stated reason (cancellation_details).
Failed payment, retries leftinvoice.payment_failed with next_payment_attempt setInvoluntary churn in progress. Often recoverable.Depends on the decline code (see below).
Failed payment, retries overinvoice.payment_failed with next_payment_attempt = nullThe subscription is about to be canceled, marked unpaid or left past due, depending on your settings.Card-update link right away.
Seat dropcustomer.subscription.updated, item quantity went down in previous_attributesContraction usually comes before churn.Check in and offer a right-sized plan.
Downgradecustomer.subscription.updated, item price went downSame as a seat drop: a value or budget problem.Find out which feature they stopped needing.
Card about to expirecard.exp_month / card.exp_year on the default payment methodA future failed payment. The card updater fixes many (payment_method.automatically_updated), not all.A short "your card expires soon" email before renewal.
Paused or trial endingcustomer.subscription.paused, customer.subscription.trial_will_endA decision point is close.Show the value they got before the date.
Renewal coming upinvoice.upcomingAnnual customers churn on a schedule.A value recap 30 to 60 days before renewal, sooner if usage is weak.

Usage declines aren't a Stripe event. Compare each account's weekly active users or core actions with its own previous 28-day average. A drop of about 50% over 14 days is a useful starting threshold.

Decline codes: retry, ask, or stop

The decline code on a failed charge decides the first move.

GroupCodesWhat to do
Soft decline: a retry can workinsufficient_funds, do_not_honor, generic_decline, processing_errorLet Smart Retries run, then send a short note with a card-update link.
Customer has to fix itexpired_card, incorrect_number, incorrect_cvc, authentication_requiredA retry won't help. Email the customer now.
Hard decline: don't retrylost_card, stolen_card, fraudulentStop retrying. Ask for a different payment method and don't mention the bank's reason.

A weekly routine (about an hour)

  1. Pull the lists: scheduled cancellations, past_due subscriptions, seat drops and downgrades from the last 7 days, cards expiring this month or next, usage declines, and renewals in the next 30 to 60 days.
  2. Rank: two or more strong signals is high risk, one strong signal is medium, one weak signal is low. Within each band, sort by monthly revenue.
  3. Act: match the move to the signal, as in the tables above.
  4. Close the loop: log what you did and whether the customer stayed.

Before buying anything, turn on Smart Retries and the failed-payment and expiring-card emails in Stripe's Billing settings. They're free.

Run it yourself

stripe-churn-signals is a small Node.js webhook listener. It verifies Stripe signatures, de-duplicates retried events and writes each signal above to a CSV. It makes no Stripe API calls. The repo also has a weekly checklist.

Maintained by North Metric, churn prevention for SaaS on Stripe. Code is MIT licensed. Webhook field names can change between Stripe API versions, so check them against the version your account is pinned to.
